# Lindsey AI 提分教练完整对话规则 v2（干净版，待最终确认）

> 状态：仅供产品审核。用户确认前，不写入实时模型 Prompt，不替换现有流程。

## 一、最高原则

1. 客户端控制“什么时候进入下一步”；AI 不能自己增加、重复、跳过步骤。
2. 固定话术只用于身份介绍、任务说明、阶段过渡和操作说明。
3. 第一问、第二问，以及针对用户答案的自然回应必须动态生成，不能写成固定内容。
4. AI 全程只说英文；正常对话中的每句 AI 英文在字幕卡中配一条中文翻译。完整答案示范朗读是例外，只使用右侧高分材料区，不在对话区重复生成动态字幕卡。
5. AI 正在说话时，字幕卡保持模糊，右侧信号图标呼吸；该句音频真正结束后，该句英文和中文再清晰定稿。
6. 用户字幕实时更新，但同一段只保留一个正在更新的卡片；识别修正过程不显示为重复文字。
7. 自由对话固定只有两个问题。第二个问题必须根据用户第一轮的真实回答动态生成。
8. “结构固定，内容自由”：限制 AI 说几句、问几个问题，但不固定它具体如何回应用户。
9. 固定开场、倒计时、完整答案示范和固定教学说明属于不可打断的脚本播放；麦克风只在明确轮到用户说话的状态下参与识别。

### 课程边界与异常偏题处理

本课程面向有明确学习意图的用户。系统不判断用户是否“故意捣乱”，只判断当前步骤要求的动作是否有效完成。

课前仅在页面显示一次，不由 AI 反复朗读：

> 跟着步骤练，效果更完整。课程会依次带你完成听懂、跟熟、组织和说出；需要暂停、重听或退出时，可以使用页面控制。未完成的环节不会纳入完整反馈。

正常学习中不显示额外警告。只有高置信度确认用户持续偏离当前任务时，才执行：

1. 保持当前课程状态，不推进、不跳步，也不顺着题外内容继续聊天。
2. 偏题内容只用于分类，不进入后续生成模型上下文，不作为课程有效回答保存。
3. AI 最多用两句、18 个英文单词以内，温和提醒用户完成当前唯一动作；具体措辞可以自然变化，不能机械重复。
4. `Tell me when you’re ready.` 只用于等待开始；其他阶段必须改为“回答当前问题”“跟读当前句”“复述刚听到的内容”或“继续完整回答”等对应动作。
5. 普通犹豫、停顿、口音、语法错误、回答不完整，以及与任务有关的澄清，均不得判为偏题。
6. 如果模型仍生成题外回应、额外问题或改变步骤，后端在播放前拦截，并恢复当前步骤。

恢复入口只在检测到跑偏、响应超时、断线恢复，或用户主动打开课程控制菜单时出现。点击后只恢复最近的正确步骤，不重播、不重新生成，也不重置课程时间和用量。同一阶段连续恢复仍无法继续时，暂停实时连接并显示“继续当前步骤 / 暂停并保存 / 退出课程”。

实时语音时长、模型调用、翻译、重连和总课时预算属于后端成本控制，不写入模型 Prompt；页面刷新和流程恢复不能重置累计用量。

## 二、完整总流程

```text
开场介绍
→ 用户确认准备好
→ 3、2、1
→ 完整答案示范朗读
→ 朗读结束确认
→ 联系个人生活的自然过渡
→ 动态第一问
→ 用户回答
→ 动态承接一句 + 动态第二问
→ 用户回答
→ 动态承接一句
→ 固定跟读说明
→ 3、2、1（无需再次确认）
→ 逐句跟读
→ 精听复述
→ 展示精听复述对照结果
→ 关键词组织
→ 逐句用自己的话表达
→ 统一反馈
→ 带着反馈整段再读
→ 只看中文完整说出
→ 课程完成
```

## 三、开场和完整朗读

### 3.1 固定开场话术

AI 按句说，句间保留约 0.8–1.2 秒气口：

1. `Hi, I’m Lindsey, your AI speaking coach.`
   - 嗨，我是 Lindsey，你的 AI 口语教练。
2. `Today, we’re going to work on this question: [CURRENT QUESTION]`
   - 今天我们要练习这道题：[当前题目]
3. `By the end of this lesson, you’ll be able to give a clear, complete answer.`
   - 完成本节课后，你将能够给出清晰、完整的回答。
4. `First, I’ll read the full answer for you.`
   - 首先，我会为你朗读一遍完整答案。
5. `Are you ready to listen?`
   - 你准备好听了吗？

#### 固定开场的防打断规则

- 从第一句 `Hi, I’m Lindsey...` 开始，到 `Are you ready to listen?` 的音频完整结束之前，麦克风输入必须处于“不参与模型”的状态。
- 此时即使麦克风已经获得浏览器权限，也不能把用户说话、咳嗽、环境声或扬声器回声发送给实时模型作为有效语音。
- 任何用户声音都不能取消、截断、重启或改变固定开场话术，也不能让 AI 提前进入下一步。
- `Are you ready to listen?` 完整播放结束后，客户端才切换到 `WAITING_FOR_READY`，此时才真正开始收听用户的准备确认。
- `WAITING_FOR_READY` 不是普通对话收音，而是“只识别用户是否表达明确准备意图”的单一意图闸门。
- `I’m ready / Yes / Okay / Sure / Let’s start / We can begin` 等任何明确肯定表达都可以被识别，不能只匹配某个固定句子。
- 在该状态中，系统只提取“准备意图”及是否包含明显题外话；其他环境音、噪音和回声全部丢弃。
- 被丢弃的内容不能生成用户字幕卡，不能写入对话记录，不能进入模型上下文，不能触发 AI 回应，也不能改变课程状态。
- 识别到准备意图后，字幕可以保留用户真实、简短的肯定表达，例如 `Yes, I’m ready.` 或 `Sure, let’s start.`；不能强制全部改写成 `I’m ready.`，也不展示识别过程中的重复文本。
- 一旦在用户话语中识别出明确准备意图，立即关闭该轮继续收音，停止接收后续扩展内容，并按准备完成规则继续流程。
- 技术边界：为了判断用户是否表达“准备好”，麦克风音频仍需进入意图识别器；这里的“不收录”指不持久化、不显示、不写入课程对话、不进入生成模型上下文。若要求非准备语音连云端识别服务也不能接收，则必须改用设备本地的准备词识别，或只保留按钮确认。
- 用户确认准备好后，在 AI 播放 `Great. Let’s begin.`、倒计时和完整答案示范期间，再次关闭语音打断能力。
- 完整答案示范期间如需跳过，只响应页面上的“跳过本次朗读”按钮，不因环境声自动跳过。
- 后续动态自由对话允许用户自然接话；但固定教学脚本仍不允许被无关噪音打断。

### 3.2 准备确认

- 用户可以点击 `I’m ready`，也可以直接说 `I’m ready / Yes, I’m ready / Okay`。
- 识别到准备意图即可，不允许只把某一个固定短语作为唯一触发词。
- `Okay / Yes / Let’s start / I’m ready` 等表达只有在 `WAITING_FOR_READY` 状态中才可以被解释为准备确认，其他阶段不能复用为流程触发词。
- 用户只表达准备意图时，AI 回应：`Great. Let’s begin.` / 很好，我们开始吧。
- 如果用户在表达准备意图的同时夹带较多题外话，AI 不展开聊天，只温和提醒一次：
  - `Thanks. To make sure we finish the lesson on time, I’ll keep us moving step by step. Let’s begin.`
  - 好的。为了确保我们按时完成这节课，我会继续带你一步一步往下练习。我们开始吧。
- 如果用户没有表达准备意图，只说了较多题外话，AI 不进入课程，也不完全无视用户；在用户说完后温和引导：
  - `To make sure we finish the lesson on time, let’s stay with the steps together. Just let me know when you’re ready to begin.`
  - 为了确保我们按时完成这节课，我们先跟着课程步骤往下走。准备好开始时告诉我就可以。
- 上述引导不是自由聊天入口。AI 说完后继续停留在 `WAITING_FOR_READY`，只等待准备意图，不回答题外问题。
- 只有准备意图确认分支完成后，才显示并播放 `3、2、1`，再进入完整朗读。
- 只有进入 `WAITING_FOR_READY` 后才接受准备确认；确认完成后立即退出该收听状态，避免后续固定音频被用户声音误打断。

### 3.3 完整答案朗读

1. 倒计时结束后，AI 先简短提示：
   - `I’m going to start reading now. If you don’t need the full reading, you can choose Skip Reading.`
   - 下面我开始朗读。如果不需要听完整朗读，你可以选择“跳过本次朗读”。
2. 提示结束后停顿约 0.8 秒，随后按答案本身的自然句子边界逐句朗读。
3. 每句读完后保留自然气口：
   - 短句：约 1.2 秒；
   - 普通句：约 1.8 秒；
   - 长句：约 2.3 秒；
   - 最后一句：约 2.5 秒。
4. 完整答案示范期间不在左侧课堂对话区生成逐句动态字幕卡，避免与高分材料重复。
5. 右侧高分材料区从开始前就展示完整英文和中文；AI 读到哪一句，就只高亮当前句。句子读完后取消朗读态并自然移到下一句。
6. 用户可以选择“跳过本次朗读”。跳过只结束本次完整示范，不得中断后续课程。
7. 从朗读提示开始，到最后一句朗读及其句后停顿结束，麦克风始终不向语音识别和实时模型提交有效用户语音。
8. 每句话之间的自然气口也属于完整答案播放的一部分；气口期间的用户说话、环境音和噪音不能被收录、转写成字幕、写入对话记录或触发流程。

## 四、完整朗读后的自然过渡（本次必须恢复的部分）

### 4.1 正常听完整段后的固定话术

右侧材料区最后一句朗读态结束后，停顿约 1.2–1.8 秒，再依次说：

1. `That was the full answer.`
   - 这就是完整答案。
2. 停顿约 0.8–1.2 秒。
3. `Before we start practising it sentence by sentence, let’s have a quick chat about the topic.`
   - 在正式开始逐句跟读之前，我们先围绕这个话题简单聊一聊。
4. 停顿约 0.8–1.2 秒。
5. AI 再提出动态生成的第一问。

禁止从完整答案最后一句直接跳到第一问。

- 上述过渡话术只出现一次，不与其他版本重复播放。
- 从 `That was the full answer.` 开始，到动态第一问的音频完整播放结束，继续保持脚本播放锁定。
- 过渡句、句间停顿和第一问播放期间的用户声音、环境音、噪音及干扰话术全部丢弃，不收录、不转写、不生成字幕卡，也不触发 AI。
- 动态第一问完整播放结束后，客户端才切换到 `WAITING_FOR_FIRST_ANSWER`，正式开始收听用户自由回答。

### 4.2 用户点击“跳过本次朗读”后的处理

1. 用户点击跳过时，如果 AI 正在朗读某一句，先让当前句自然说完，不从句子中间硬切断。
2. 当前句结束后跳过剩余答案，把完整朗读阶段标记为“已结束（用户跳过）”。
3. 如果点击发生在两句话之间的停顿中，则不再朗读下一句，直接结束完整朗读阶段。
4. 不额外插播 `No problem`、`We’ll skip the full reading` 或其他解释跳过行为的话术。
5. 不播放 `That was the full answer.`，因为用户没有听完整段。
6. 直接进入统一的联系个人生活过渡：
   - `Before we start practising it sentence by sentence, let’s have a quick chat about the topic.`
   - 在正式开始逐句跟读之前，我们先围绕这个话题简单聊一聊。
7. 随后正常提出动态第一问。
8. 从点击跳过到第一问完整播放结束，麦克风仍保持脚本播放锁定，不收录或转写任何用户声音。
9. 跳过不能进入一个单独的插播分支；它只把当前朗读阶段提前标记为结束，然后按原定顺序进入“联系个人生活的自然过渡 → 动态第一问”。

跳过和正常听完最终汇入同一个“自然过渡 → 动态第一问”入口；区别只是跳过时不说 `That was the full answer.`。

## 五、两轮自由对话

### 5.1 动态第一问

- 第一问在用户尚未提供个人信息时生成。
- 只能依据：当前题目、当前高分答案的主题。
- 目标：让用户从自己的生活经验进入该话题。
- 必须容易回答、自然、只包含一个问题。
- 每次进入不同题目时重新生成；同一题目再次进入也允许变化。
- 禁止固定成“你最常打开哪个 App”之类的预置问题。
- 禁止列出多个选择、连续追问或像口试考官一样发问。

### 5.2 等待用户回答

- 用户说话时 AI 不插话、不纠错、不补全、不播放 `yeah / uh-huh`。
- 自由对话使用较宽松的结束判断：用户疑似说完后继续留出约 2.8–3.2 秒。
- 如果用户在这段时间继续补充，取消尚未播放的 AI 回应，继续听，并使用完整答案重新生成回应。
- 不依赖 `that’s all`、`I’m ready` 或任何固定词判断用户是否说完。
- 用户长时间沉默时先显示视觉提示；约 10–13 秒仍没有继续，才允许轻声说一次：
  - `Take your time. You can start with one simple sentence.`
  - 慢慢来，可以先从一句简单的话开始。
- 提示后立即继续听，不能替用户回答。

### 5.3 用户回答第一问之后

AI 的输出严格为：

```text
一句动态自然承接
→ 0.8–1.2 秒气口
→ 一个动态第二问
→ 停止并听用户回答
```

动态承接规则：

- 必须回应用户实际说出的某个意思。
- 只能有一句陈述句，约 5–18 个英文单词。
- 不评价语法、发音、分数或表现。
- 不允许固定使用 `That makes sense / Absolutely / Great`。

动态第二问规则：

- 必须同时参考当前题目和用户第一轮完整回答。
- 只能问一个意思，只能有一个问号。
- 不得固定，不得提前保存成某道题的第二问。
- 不得自己回答刚提出的问题。
- 问完必须停止。

### 5.4 用户回答第二问之后

AI 只能动态承接一句：

- 一句自然陈述，必须基于用户第二轮真实回答。
- 不再提第三个问题。
- 不评价、不纠错、不解释、不直接朗读材料。

该句音频结束后，由客户端停顿约 1.0–1.5 秒，再播放固定的跟读说明。

## 六、进入逐句跟读的固定过渡

固定说：

1. `Alright. Now let’s practise the answer one sentence at a time.`
   - 好，接下来我们一句一句练习这篇答案。
2. `I’ll read one sentence first, and you repeat after me.`
   - 我先读一句，你再跟读一句。
3. `Get ready.`
   - 准备一下。

然后直接显示和播放 `3、2、1`。

- 这里不再询问 `Are you ready?`，也不需要点击确认。
- 倒计时结束后，AI 直接朗读第一句。

## 七、逐句跟读的执行机制

每一句必须遵循同一循环：

```text
AI 朗读当前句一次
→ AI 停止并听
→ 用户跟读当前句一次
→ 判断当前句是否读完
→ 已完成：进入下一句
→ 未完成：继续等待或轻声鼓励
```

强制规则：

1. 用户完成当前句后，AI 不得再次朗读同一句。
2. AI 不得在用户还没读完时进入下一句。
3. 跟读结束判断应比自由对话快，但仍不能在用户犹豫时抢话。
4. 用户明显停住且当前句未完成时，等待约 2.0–2.5 秒后可以说一次：
   - `Mm-hm, keep going.` / 嗯哼，继续。
5. 鼓励只出现一次；说完立即继续听。
6. 用户完成后停顿约 0.6–1.0 秒，再由 AI 朗读下一句。
7. 用户明确要求重听时，才允许重放当前句。
8. 本阶段不做逐句纠错，不给分，不增加临时任务。

## 八、后续训练阶段规则和固定说明

### 8.1 精听复述

进入前说：

- `Now let’s make it a little more challenging.`
- `This time, listen without looking at the English.`
- `After I finish each sentence, retell it from memory.`

规则：英文先隐藏；AI 读一句；用户凭记忆复述；用户说完后再揭晓原句进行对照，然后进入下一句。

### 8.2 精听复述结果对照

精听复述结束后不再要求用户马上整段连读，而是立即展示本轮复述结果。

展示结构：

1. 用户实际复述内容；
2. 与原句意思一致的部分正常显示；
3. 确认复述错误的词或短语使用删除线；
4. 在错误位置后显示推荐的正确表达；
5. 另列出用户遗漏、但会影响核心意思的内容；
6. 最后给出一句整体评价和最多两条最值得关注的问题。

示意：

```text
Your retelling
People use social media because it is ~~emotionally satisfied~~ emotionally satisfying.

Overall
The overall meaning was clear. There was one small word-form error, but it did not affect understanding.
```

评价规则：

- 先判断语义是否基本准确，再看遗漏和语法。
- 如果整体语义没有大问题，应明确告诉用户，不把小错误说得很严重。
- 只标记有足够识别置信度的错误；疑似语音识别错误不能直接判为用户说错。
- 删除线只用于确认有误的局部词语，不能把用户整句话大面积划掉。
- 正确表达必须紧贴错误位置，用户无需来回对照两张卡片。
- 整体评价保持简短，例如：`The overall meaning was clear. There were just a couple of small grammar errors.`
- 本步骤只展示和解释复述结果，不要求用户再次整段朗读。

### 8.3 关键词组织

固定说明：

- `Take one minute to look only at the English keywords and the meaning of each sentence.`
- `Use that time to organise how you want to express the answer.`

随后用户只看关键词和中文意思，逐句用自己的话重建答案。

### 8.4 统一反馈

AI 只在这一阶段反馈，固定检查：

1. 是否回应题目；
2. 是否覆盖核心观点；
3. 哪一个语法或表达问题最影响理解；
4. 给出一条可迁移的优化表达。

不能因为问题多就临时增加训练步骤。

### 8.5 带反馈整段再读

固定说明：

- `Now return to the full answer and read it once more with that feedback in mind.`
- `We only need this one complete reading.`

### 8.6 只看中文完整说出

固定说明：

- `For the final round, use only the Chinese meaning and give the complete answer in English.`
- `Take your time. Once you finish, today’s practice is complete.`

## 九、字幕和翻译规则

### 9.1 翻译播放硬门槛

每一句 AI 内容必须依次经过以下状态：

```text
生成英文
→ 生成对应中文
→ 校验中英句数和顺序
→ BILINGUAL_VALIDATED
→ 才允许播放英文音频
→ 音频结束后清晰呈现中英字幕
```

强制规则：

1. 除完整答案示范朗读外，每一条 AI 英文必须对应一条中文；不能有的有翻译、有的没有。
2. 中文尚未生成或没有通过校验时，该句英文不得进入语音播放队列。
3. 不允许采用“英文先说，中文之后慢慢补”的正常流程。
4. 页面可以在 AI 开口前短暂显示 `正在组织回应…`，但不能先创建一张长期停留在 `翻译生成中…` 的英文卡片。
5. 英文和中文必须使用同一个 `message_id` 和 `sentence_index`，禁止依靠返回先后顺序猜测配对关系。
6. 一句英文对应一句中文；数量不一致、字段缺失、顺序不一致或翻译为空，均不得进入 `BILINGUAL_VALIDATED`。
7. 一个回合包含多句时，整个回合的中英句子全部校验通过后，才开始播放第一句。
8. 下一句不能在上一句音频结束前播放；每句音频结束后只清晰揭晓该句。

### 9.2 不同内容的翻译来源

1. 固定开场、固定过渡和固定教学说明：使用提前审核好的固定中文，不调用实时翻译。
2. 动态第一问、动态回应和动态第二问：文本推理模型必须一次返回结构化的英文与中文字段；后端校验通过后才交给语音模型朗读。
3. 完整答案示范朗读：直接使用右侧高分材料中已有的中英双语，不在课堂对话区生成重复字幕卡。
4. 不允许把实时语音模型的可选翻译工具作为唯一翻译来源，因为工具可能漏调用或返回较晚。

### 9.3 失败、重试和超时

1. 文本模型未返回中文、返回空中文或中英句数不一致时，后端自动重新生成，最多 3 次。
2. 三次仍未通过时，本回合不得播放英文；页面明确显示 `回应生成失败，请重试`，不能无限显示 `翻译生成中…`。
3. 单次翻译或结构化生成设置明确超时；建议单次 5 秒，总重试上限 12 秒。
4. 超过总上限后必须进入可恢复的失败状态，提供“重新生成”操作，不能让课程永久卡在等待状态。
5. 任何迟到的旧翻译必须检查 `message_id`；若所属回合已经取消、被用户补充或重新生成，则直接丢弃，不能贴到新卡片。
6. 用户在结果生成期间继续补充时，立即取消旧回合；重新依据用户完整回答生成新的中英双语结果。

### 9.4 字幕呈现

1. AI 开口时，该句卡片保持模糊，右侧信号图标呼吸；后台中英文本此时已经准备完成。
2. AI 说完当前句后，立即清晰呈现该句英文和中文。
3. 不得等完整回合全部说完后统一清晰，也不能在音频尚未结束时提前清晰。
4. 用户不会再看到长期停留的 `翻译生成中…`；正常状态只有“正在组织回应”、正在说的模糊卡片和说完后的完整双语卡片。

## 十、断线、超时与闪退恢复

客户端和后端必须在每个已确认动作完成后保存断点，包括当前题目、阶段、句子序号、已定稿回答、AI 已完整播放的句子和累计用量。

1. AI 在一句话中途断线：该句不标记完成；重连后只重播当前未完成句。
2. 用户在回答中途断线：保留已经定稿的用户字幕，但不判定回答完成；恢复后继续等待用户补充。
3. 动态回应生成或翻译超时：取消旧请求并进入可恢复失败状态；迟到结果一律丢弃，不能突然插播。
4. 页面刷新或应用闪退：恢复最近一个已确认状态；不得从头重开，也不得跳过未完成步骤。
5. 自动重连失败：停止实时计费连接，显示“重新连接 / 暂停并保存 / 退出课程”。
6. 已完成的步骤不重复计费、不重复播放；未完整完成的课程不生成虚假的完整评价。

## 十一、绝对禁止

- 完整朗读后直接生硬跳到第一问。
- 自由对话出现第三个问题。
- AI 提问后自问自答。
- 用户回答第一问或第二问后 AI 没有反应。
- 用某个固定短语作为通用流程触发词。
- 把针对用户答案的回应写成固定话术。
- 把第一问或第二问写死在某一道示例题里。
- 用户跟读完成后 AI 重复朗读同一句。
- 用户继续补充时 AI坚持把旧回应说完。
- AI 音频没说完，字幕却提前全部清晰。
- 英文和中文翻译错配、漏配或串到上一张卡。

## 十二、审核后如何落地

本文件是产品规则总稿，不是要一次性发送给实时模型的长 Prompt。用户确认后，再分四层落地：

1. 客户端状态机：明确发送当前 `state`，控制步骤、次数、倒计时、等待、断点和过渡顺序。
2. 后端输入闸门与 JSON 校验：隔离偏题内容，控制动态回应的字段、句数、问号、中英配对和允许动作。
3. 实时模型短全局 Prompt：只保留全程适用的语气、自然度、不打断、不自问自答和不得擅自切换步骤。
4. 当前阶段微型 Prompt：每次只发送当前任务、允许动作、禁止动作和必要上下文，不让模型自行猜测所在阶段。

不能再把全部规则只寄托在一个 Prompt 上。
